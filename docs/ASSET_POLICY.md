# 美术素材政策

用户的角色稿件、兽装照片和角色像素图默认保持原样并留在用户掌握的位置。使用、修改、AI 重绘、图生图、裁切、抠图、局部补全、改色、外观修改、衍生角色和融入新场景均需用户明确授权。后续获准展示的原图按授权范围完整、等比例展示。

## 模块制作流程

先确认布局和清单，再制作真正透明的 PNG，检查像素质量与色板，交由用户验收，最后离线组合背景并叠加网页功能组件。素材可为独立物件，也可为构图完整、彼此关联的酒馆场景组；场景组仍须是可复用的独立模块，不能替代整幅背景。生图保持统一像素密度、描边、光照、透视和色板。

CP2 的酒杯、木桌和蜡烛三个原创透明像素素材已于 2026-11-07 获用户确认，允许在 CP3 场景组合中复用。

CP3 返修在已制作模块之外增加融合式透明酒馆场景组，以及独立的“凌巽的酒馆”艺术字 PNG。场景组须有明确的建筑/陈设关系与视觉焦点，不得把酒杯、蜡烛、酒桶等互不关联地摆成图标陈列。标题图只含指定五字及其装饰，不包含栏目文案；栏目文案由网页以本地简中像素字体渲染。所有新图沿用 V2 固定十色、清晰硬边、统一像素密度与光照。每项新增图均保留文字提示词、源稿和交付文件；不得将用户角色原稿或其参考图作为生图输入。

通过 `assets/layouts/cp3-tavern.json` 保存可编辑的位置、比例、重复方式与旋转设置，以离线脚本组合 1920×1080 背景。背景不得包含文字、UI、角色或游戏画面；组合后必须把 x=40、y=144、1280×720 区域清为空 alpha，并验证画布尺寸、alpha、色板和该透明区域。另以现有 CP1 UI 叠加生成独立预览，不把 CP3 美术合入直播路由。

完整场景一键生图和将整幅插画切成区域的方式不符合模块制作规范。新增的场景组必须保持透明、独立，并通过布局配方与墙地纹理等模块离线组合。复杂 CSS、SVG 路径或 Canvas 场景绘图同样不作为主体美术。CSS 用于布局、文本、简单边框和基础交互，SVG 可用于功能图标。

## 文件与清单

CP3 追加素材为独立右上酒馆陈设组与“酒馆留言板”透明艺术字图，两者均以纯文字提示词生成并保留源稿。艺术字属于 UI 叠加资产，背景组合脚本按素材类别拒绝纳入文字图。

评论区与播放区分别交付中英文组合透明艺术字，内容为“酒馆留言板 / COMMENT”和“正在播放 / NOW PLAYING”。较小的英文字样与中文做适量前后叠压，均作为同一图像生成并统一像素尺度和色板。

公告组件增加独立的“酒馆公告 / ANNOUNCEMENT”组合艺术字，保留生成提示词与源稿；使用真实透明通道、统一像素尺度与固定色板，作为 UI 叠加资产单独验收，不纳入无文字背景。

用户要求公告标题改用内置 imagegen，并以本项目已生成的栏目标题作为风格参考。外部 API 尝试稿保存在本地忽略目录，仅登记内置生图交付稿。

`assets/manifest.json` 登记名称、独立路径、来源、生成方式、提示词文件、版本、逻辑尺寸、用途、许可和用户确认状态。目录分为 `generated`、`backgrounds`、`ui` 和 `user-originals`。用户原稿目录默认忽略 Git，当前运行资源中没有用户角色原图。

清单按当前阶段登记素材路径、生成方式、提示词文件、版本、实际像素尺寸、用途、许可和用户确认状态。生成源文件和验收结果分开保存。CP2 的三个条目保持 `APPROVED`；CP3 返修资产与背景在用户验收前标为 `WAITING_USER_REVIEW`。CP3 同时提供 UI 叠加预览和可调整的物件布局配置。第三方字体须附上游版权与许可证文件。

## 质量与来源

PNG 必须具有实际透明通道，检查边缘残留与伪棋盘背景。质量不符时修改或暂缓采用。开源或第三方素材先核对作者原始页面的许可，再保留原文、署名与文件清单。免费可见和允许复用分开核实，来源不明的作品仅供观察。

此前已提供的参考图仅作为需求背景记录。V2 生效后，新增 AI 输入按本文件重新核对授权范围。既有美术草稿保存为本地备份，活动页面恢复灰度线框。
