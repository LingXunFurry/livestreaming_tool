# 本地运行架构

Node.js 最低版本 22.12。首次初始化运行 `npm ci`，之后通过 `启动直播间.bat` 或 `start.bat` 启动。脚本定位自身目录，检查 Node.js，调用统一运行管理入口。前端由 Vite 构建，运行期间只需要一个 Node.js 服务。

## 生命周期

启动器读取项目身份与本地运行记录，复用同一实例。启动锁覆盖配置初始化、构建和服务就绪过程。新实例检查依赖、程序文件、配置与端口，创建后台进程并等待 `/health` 与实例身份匹配，随后打印实际端口的三个页面 URL。

服务采用独立后台进程，Windows 子进程窗口隐藏，启动命令窗口关闭后服务继续运行。`server.openAdminOnStart` 控制是否打开后台，默认关闭。项目默认没有开机自启动，重启电脑后再次运行启动入口。

停止入口通过本地运行记录和随机控制令牌请求当前项目服务正常关闭。服务关闭 WebSocket、内部心跳和 HTTP，清理自己的运行记录。停止入口不按进程名称批量结束程序。原来的开发预览属于独立开发命令，管理器检测到其端口占用时报告冲突。

## 状态与端口

默认 `127.0.0.1:3000`。端口在 `data/settings.json` 配置，诊断测试也可使用 `TAVERN_PORT`。主机限定为 `127.0.0.1`。端口被其他程序占用时显示尝试端口及处理办法，由用户更改配置或关闭对应程序。

`RUNNING` 表示服务与基础页面可用。`STOPPED` 表示当前项目实例未运行。`DEGRADED` 表示基础服务运行但已启用的可选适配器不可用。`ERROR` 表示配置、文件、端口或实例状态异常。未启用的适配器状态单独显示，不影响基础服务就绪。

`/health` 返回就绪和实例标识。`/api/runtime/status` 返回版本、启动时间、实际端口、页面、WebSocket 和适配器状态。公开接口省略控制令牌、凭证、Cookie 和本机绝对路径。

## 日志和恢复

结构化日志位于 `data/logs/runtime.log`，达到 1MiB 后轮换，保留三个历史文件。记录启动、停止、关键错误、WebSocket 连接事件和适配器状态。日志过滤凭证类字段。

异常退出后再次运行启动入口，健康与身份检查会识别失效记录。死进程留下的启动锁可自动清理，存活进程所属的锁保留。当前采用明确重新启动的恢复方式，自动守护与长期恢复压力测试在 CP8 验收。

缺少网易云桥接器或 B 站授权时显示未连接或未配置，CP0 仍可正常运行。凭证和外部服务自动启动能力等待对应适配器阶段核验。
