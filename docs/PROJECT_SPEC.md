# 产品规范

本规范落实 `V2_BRIEF.md`。CP0、CP1、CP2 已由用户验收通过，当前范围为 CP3 模块化酒馆场景组合。保留已通过的区域位置与比例；CP3 场景只在独立验收预览中展示，不修改直播源。

## 最终目标

以凌巽的酒馆为主题，建立本地 Web 直播装修系统。首期固定 1920×1080 横屏，游戏内容保持画面主体。一个服务同时承载 B 站、抖音和统一后台。直播软件负责游戏、音频与编码推流，网页负责透明装饰层。OBS 是可选工具。

## 页面

| 路由 | 职责 | 当前布局 |
| --- | --- | --- |
| `/live/bilibili` | B 站独立直播源 | 透明线框与明确标注的示例内容 |
| `/live/douyin` | 抖音独立直播源 | 留言板线框与明确标注的抖音示例内容 |

| `/health` | 就绪检查 | 实际服务状态 JSON |
| `/api/runtime/status` | 组件状态 | 实际进程、页面、WebSocket 与适配器状态 |

两个直播页面可同时存在。全局信息和视觉复用，平台配置分别保存。平台专属数据故障隔离。后台完整编辑与广播属于 CP5。

## 后续功能

B 站与抖音采用相同的酒馆背景、艺术字与留言板样式。每个平台通过自己的专属页面显示本平台弹幕，分别设置直播间地址，分别连接、保存设置和报告状态。B 站互动消息可包含弹幕、礼物、连续赠礼、大航海和 SC，抖音事件按实际适配器支持范围处理。网易云适配器提供经过实测的歌名、艺术家、播放状态、进度与同步歌词。歌词关闭后右侧主面板扩展。

场景按后续检查点提供游戏直播、酒馆夜话、开播等待、暂时离席、酒馆打烊。统一后台最终支持双平台预览、场景切换、全局委托、平台独立设置、状态监控、设置保存和备份恢复。

## CP0 已完成范围

交付规范、统一启动/关闭/状态入口、配置模块、基础 HTTP/WebSocket 服务、日志、三个基础页面、健康检查和迁移设计。真实网易云、B 站事件、完整后台交互、正式美术与场景合成在对应检查点实现。竖屏、Windows 安装包及免安装运行环境属于后续可扩展内容。

## CP2 已通过范围

## CP3 当前范围

用户明确将抖音从任务公告模式调整为留言板模式。两个平台外观一致，各自使用独立消息列表和专属路由。CP3 交付平台标记清楚的静态示例，真实房间地址设置与采集连接按后续配置及接口检查点验收。方法调研见 `DANMAKU_SOURCES.md`。

CP3 首版因道具孤立、场景缺乏整体视觉焦点而返修。返修可增加透明的融合式酒馆场景组，并单独生成“凌巽的酒馆”五字标题图；场景预览中的栏目和 UI 文案使用随项目分发、覆盖简体中文的像素字体。通过离线脚本和可编辑 JSON 组合 1920×1080 无 UI 背景，继续遵守 V2 色板与真实 alpha。透明游戏区保持 x=40、y=144、1280×720，所有已验收 CP1 区域位置和比例不变；只在 `/scene/review` 验收，不改动直播源或推进 CP4。

CP3 追加调整采用独立的右上酒馆陈设组，使左右两端形成不同的布置。底部柜台的布局区域与游戏窗口左右边线对齐，均从 x=40 延伸至 x=1320。B 站评论区的“酒馆留言板”增加独立透明艺术字图，其他栏目继续采用本地像素字体。

吧台对齐以图像不透明轮廓的可见左右端点为准，离线组合时裁去素材透明留边，可见跨度为 x=40 至 x=1320。

吧台通过延长中间木面达到目标跨度。游戏木梁以不透明部分为定位依据，四条内边紧贴游戏矩形的 x=40、x=1320、y=144、y=864，四角闭合，游戏窗口完整处于木框内。

右上酒桶挂杯陈设组放大，并使不透明轮廓最右端与留言板右边线 x=1880 对齐。B 站留言板去掉“02 / 留言”，将中英文组合艺术字上移，重新分配标题、说明与评论之间的间距。

留言板与播放区艺术字按不透明轮廓左边界定位，消除生成图透明留边造成的视觉缩进，使可见左端与各自下方正文的起始线 x=1384 对齐。

评论区“酒馆留言板”与较小的 `COMMENT` 组合成同一张透明艺术字图，播放区“正在播放”与较小的 `NOW PLAYING` 同样组合制作。英文采用艺术化字形，与中文有适量前后遮挡关系，保持中英文可辨识。
