# 技术架构

保留现有 React、TypeScript、Vite 前端。运行时采用 Node.js HTTP 服务和 `ws`，同一监听端口托管构建产物、两个直播页面、后台、健康接口和 WebSocket。目录保持 `src/`、`server/`、`scripts/`，当前规模采用简洁单项目结构。

## 路由和数据流

CP2 展示板 `/assets/review` 复用现有静态服务。三件独立 PNG 由 Vite 构建为页面资源，来源与归一化过程记录在 manifest 和提示词中。制作脚本是离线 Windows 工具，运行服务使用交付 PNG。

`/live/bilibili` 与 `/live/douyin` 分别渲染共享装饰组件，平台身份由路由确定。预览页平台选择只影响预览。`/admin` 在 CP0 读取 `/api/runtime/status` 并订阅 `/ws` 的运行状态快照。`/health` 供启动器判断就绪。

普通配置经 `server/config.mjs` 统一校验和持久化。CP0 建立配置和运行状态骨架。CP5 再将后台编辑经服务端验证、原子保存和 WebSocket 广播应用到对应页面，平台专属字段与全局字段独立。

## 适配器边界

网易云适配器未来输出歌曲、艺术家、播放状态、进度和同步歌词，具体播放器桥接方式在 CP6 实测后选择。B 站适配器未来将授权事件转换成统一互动流，包含重连和连续赠礼处理。CP0 仅显示真实的未接入/未配置状态。

适配器内部错误进入组件状态和日志，网页服务继续运行。外部 Now Playing 程序属于可选依赖，启动器只能检测或管理项目明确拥有的子进程。共享歌词服务和平台独立控制在 CP5–CP7 分步实现。

## 持久化与隔离

普通设置位于 `data/settings.json`，敏感信息单独保存并忽略 Git。PID、实例标识、控制令牌和启动锁放在 `data/runtime/`，用于本机进程管理，迁移后重新生成。静态服务只开放构建目录，默认监听回环地址。
