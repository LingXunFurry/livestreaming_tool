# 技术架构

CP7 当前交付使用 `server/collector.mjs` 控制 B 站本机采集器，连接 `/ws/ui` 和 `/ws/data`，支持一键开始、停止与可选自动采集。连接及重连时核对平台和房间，停止时核对采集任务归属。抖音固定公告。`/ws/ingest/bilibili` 继续支持既有主动推送配置。事件统一规范化、去重并保存最近 100 条，再通过 `/ws` 向对应页面广播，页面重连时恢复消息快照。接收端限制消息大小并纯文本显示采集内容，关闭服务时清理自有连接。

Windows 桌面入口位于 `desktop/main.cjs`。Electron 原生菜单复用现有后台、场景与素材页面，实时源在独立窗口等比缩放。子进程通过 Electron 的 Node 模式执行统一运行入口，封装版以 `TAVERN_PREBUILT=1` 验证现成构建产物，配置位于用户目录。关闭窗口可保留服务，再次打开复用同一实例。

保留现有 React、TypeScript、Vite 前端。运行时采用 Node.js HTTP 服务和 `ws`，同一监听端口托管构建产物、两个直播页面、后台、健康接口和 WebSocket。目录保持 `src/`、`server/`、`scripts/`，当前规模采用简洁单项目结构。

## 路由和数据流

CP2 展示板 `/assets/review` 复用现有静态服务。CP3 验收页 `/scene/review` 将 1920×1080 无 UI 背景与既有 `Overlay` 叠加，仅供场景验收，不改变直播源路由。独立 PNG、提示词和归一化记录登记在 manifest；`assets/layouts/cp3-tavern.json` 驱动离线背景组合，脚本生成的背景 PNG 和场景预览图随项目保存。

CP3 制作复用 `scripts/prepare-cp2-assets.ps1` 的取样与色板流程，并为新增透明场景组与标题图保存独立提示词和源稿。`scripts/compose-cp3-scene.ps1` 校验离线布局的素材引用、坐标、整数比例、旋转、平铺区域和固定游戏窗口，临时 PNG 经逐像素校验后替换交付文件。场景标题和本地像素字体只在 `/scene/review` 叠加；场景布局是受 Git 管理的美术配方，运行设置继续由 `server/config.mjs` 统一处理。

布局图层可用 `sourceRegion` 指定素材内的整数像素裁切矩形。吧台使用同一素材的左段、中间短段和右段，裁去水平透明留边，并重复少量中间木面，使可见端点精确贴合游戏区两侧。各段按整数倍最近邻绘制。

`/live/bilibili` 与 `/live/douyin` 分别渲染共享装饰组件，平台身份由路由确定。预览页平台选择只影响预览。`/admin` 读取 `/api/runtime/status` 与 `/api/settings`，并订阅 `/ws` 的状态和设置变更。`/health` 供启动器判断就绪。

普通配置经 `server/config.mjs` 统一校验和持久化。CP5 的 `GET /api/settings` 只返回后台可编辑字段；`PUT /api/settings` 接受直播页全部可修改字段，即全局今日委托正文和两平台配置。顶部标题始终使用已验收艺术字，服务端固定为“凌巽的酒馆”且不接受标题写入。经服务端验证、备份及原子保存后更新内存快照并广播设置事件。进程状态不写入用户设置文件。

CP5 为每个平台保存独立的右栏显示选择、公告正文和歌词开关，并保存全局今日委托。B 站未获得互动授权时自动显示公告，获得连接后才按后台选择留言或公告；抖音固定显示公告。右栏公告出现时不渲染底部公告，右栏留言出现时才渲染底部公告。

公告正文在前端仅渲染受限 Markdown 子集（加粗和固定色板文字）；不使用任意 HTML 注入。

CP6 底部右桌使用各平台独立的 `platforms.<platform>.bottomAnnouncementText`，复用统一校验、持久化和平台专属广播。旧 `benefitsText` 保留用于兼容，不展示或自动迁移为公告；原 `fontSizes.benefits` 字号字段供底部公告沿用。右侧公告正文独立保存。

分区字号作为全局和平台设置中的 `fontSizes` 对象持久化。部分更新按已有字号逐键合并，校验对象、已知字段、整数与范围。前后端共用 `config/font-sizes.json` 的范围定义。全局字号变动向两平台广播，平台字号变动只更新目标平台，直播组件通过 CSS 变量应用数值。

CP3 先在场景验收页提供评论和公告的互斥静态预览，复用既有右栏组件和像素正文样式。CP6 按用户要求将公告标题改为像素文字，历史透明图像保留。预览选择通过页面状态及查询参数记录。

CP4 将已批准的 CP3 背景与标题用于两个直播源。模拟互动与歌曲时间轴在浏览器组件内运行，平台组件实例分别拥有状态，不经过后端、不写入设置文件、不伪装为适配器连接。纯函数负责追加事件和合并连续的同用户同礼物事件，以便独立测试；真实事件仍由 CP7 适配器提供。

## 适配器边界

CP7 房间地址以 `platforms.<platform>.roomAddress` 独立保存，复用普通配置校验、备份和后台设置同步。房间地址仅用于记录目标，不能表示平台事件已接入；实际适配器就绪前状态仍为未接入。

CP6 的旧右栏公告迁移保留兼容字段和一次性迁移标志；当前右栏公告重新作为 B 站未授权回退及抖音固定内容，底部公告仅在 B 站右栏选择留言且正文存在时显示。后台继续独立编辑两类公告正文。

CP6 音乐适配器放在 `server/music.mjs`，内部拥有超时、串行轮询和快照，生命周期由当前服务管理。GET `/api/music` 返回音乐快照，WebSocket `music.updated` 在初次连接与采样后发送。普通音乐配置包含在既有 `/api/settings`，旧请求缺失时保留当前值。POST `/api/music/control` 只接受已知控制动作和本机同源 JSON 请求，桥接失败返回组件错误并继续托管页面。歌词文本以纯文本呈现，桥接数据经过类型、长度、数值及响应大小校验。外部地址禁止凭证、非回环主机与重定向。

B 站保留独立直播间 URL/房间号和授权状态；`/live/bilibili` 只订阅 B 站事件。`/live/douyin` 复用相同装饰但不再订阅第三方抖音事件。B 站未授权时页面使用公告回退，授权连接后才显示真实事件或按设置继续显示公告。

CP7 不再提供抖音第三方采集端点；此前 Dycast 转发链路因 403/连接限制停止使用。B 站在获得授权前保持等待授权状态，页面自动显示公告。

网易云适配器输出歌曲、艺术家、播放状态、进度和同步歌词，通过第三方本机桥接读取客户端。Windows 上启用默认地址时由服务尝试启动已安装的桥接，仅关闭自身启动的进程；已占用的端口保持不动。B 站适配器未来将授权事件转换成统一互动流，包含重连和连续赠礼处理。

适配器内部错误进入组件状态和日志，网页服务继续运行。外部 Now Playing 程序属于可选依赖，启动器只能检测或管理项目明确拥有的子进程。共享歌词服务和平台独立控制在 CP5–CP7 分步实现。

## 持久化与隔离

普通设置位于 `data/settings.json`，敏感信息单独保存并忽略 Git。PID、实例标识、控制令牌和启动锁放在 `data/runtime/`，用于本机进程管理，迁移后重新生成。静态服务只开放构建目录，默认监听回环地址。
